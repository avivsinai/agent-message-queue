# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

A static HTML page that `amq-board --html --out <file>` renders from Go
`html/template`. The files are under `internal/board/web/`: one template, one
hand-written stylesheet, and one script. The board model is embedded in the
page. No external fonts, scripts, or CDNs.

## Users

- One owner who runs a fleet of coding agents (Claude Code, Codex, pi, agy,
  Cursor) on one machine, across one or more AMQ sessions of one project.
- Situation: between their own tasks, at a desk, the page open on a second
  screen or in a browser tab; sometimes on a phone at 390 px.
- Job: find what waits on them, then act in a terminal.

## Product Purpose

Turn fleet state into the next terminal action. The board answers, in this
order: what needs me, why, since when, and how complete and current this view
is. Success is "glance, copy one command, paste", and no wrong command is
possible.

## Positioning

The only board that shows agent messaging obligations (AMQ message kinds), work
trackers (beads), forge items (GitHub PRs and issues), harness tasks (Codex
goals), and token spend per worker side by side. It merges cards only on proven
same-work identity and places them from structured fields only.

## Operating Context

- Terminal-first. The board never acts: every action is a command the owner
  copies.
- Forge reads are costly: a `gh` call can open a keychain dialog, so GitHub data
  is cached for 10 minutes and shown with its age.
- The page is generated by a command and goes stale; it says how old it is.

## Capabilities and Constraints

- Work categories distinguish needs-you items, declared in-progress work, blocked work, backlog, and reply-due requests. A source
  strip (ok, degraded, unavailable, disabled, plus "partial" with what was not
  assessed), a roster per session, per-session "N unread for user" lines kept
  apart from card counts, usage per worker and limits per account.
- Read-only on every source; daemon-free; an unavailable or partial source is
  visible, never silent.
- Every card action is a complete, validated command or it is absent.
- Free text (subjects, titles) is display text; it never places or merges a
  card.
- Terminology: owner, worker/agent, handle, session, source, card, evidence,
  "Waiting on you", bead, PR.

## Brand Commitments

- The UI is built with impeccable, properly and idiomatically, to its full
  craft bar.
- Next leads with supported useful actions. Work, Backlog, and Requests are separate views; Sources and Agents provide secondary context.
- AMQ is open source: no company, tracker, host, or user names in the page,
  fixtures, or screenshots.

## Evidence on Hand

- Real board models come from `amq-board --json` (schema `amq/board/v2`) on a
  live project. They hold real session names, handles, and titles: reference
  only, never copied into fixtures or committed screenshots.
- Real data exists for AMQ roots, beads, Codex goals, and Claude, Codex, and pi
  usage. Do not fabricate Cursor, OpenCode, or Grok data.

## Product Principles

1. The owner's queue first: Waiting on you leads on every viewport.
2. Structure places, text informs.
3. No silent source: coverage and age are always visible.
4. Every action is complete and safe, or absent.
5. Readability and truthful state over density.

## Accessibility & Inclusion

WCAG 2.2 AA; keyboard-complete with ordinary Tab, Enter, and Space (no custom
shortcuts in v1); screen-reader order equals visual order; text contrast 4.5:1
including badges, 3:1 for non-text indicators; status words accompany every
color.
