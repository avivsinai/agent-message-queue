How stages are decided

Each card is in one stage. The first rule that matches decides it.

  1. In review: a linked pull request is open and is not a draft.
  2. Blocked: the tracker records a blocker.
  3. In progress: the tracker says started, or the only open pull request is a draft.
  4. Shipped: done or merged recently, with a recorded close time.
  5. Ready: assigned and not started, and nothing blocks it.
  6. Backlog: everything else that is current: open with no assignee, paused, or admitted by you.

A pull request joins a task card only when the task records it as the same work. A pull request that only names a bead stays its own card. Needs you is a flag, not a stage: it says who acts next. Older finished work is in History.

How states are decided

The board reads mail, presence, wake, and usage. It cannot see processes, so it never says a worker runs or has stopped. The first rule that matches decides a seat's state.

  1. ■ Limit reached: the account reports a reached limit whose reset is ahead, and neither this seat nor any session of the account was active after the limit was read.
  2. ▲ Stalled: mail has waited longer than the liveness window, and the last activity is older than that mail.
  3. ● Working: a usage record, or presence when no wake is live, shows activity inside the liveness window. A live wake refreshes presence itself, so with a wake only usage counts as activity.
  4. ○ Idle: the wake is live and the inbox is counted; no mail waits without an activity record.
  5. – Off: no wake and no recent activity; the inbox is counted.
  6. ? Unknown: the inbox was not counted, or mail waits and no activity was observed.

A mailbox with no live wake, no owned work, no recent activity, and no unread mail newer than the stale window is dormant. Says and Status quote the agent's own words; they are not checked.
